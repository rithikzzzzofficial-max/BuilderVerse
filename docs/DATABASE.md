# Database

One SQLite file: `data/builderverse.db` (path overridable with `DATABASE_PATH`). Created automatically on first query — no migration or seed step.

**Schema is owned by `src/lib/db.ts`**: an idempotent `SCHEMA` string runs `CREATE TABLE IF NOT EXISTS …` on boot. Dev-friendly for a single-binary app; a production system would switch to versioned migrations.

## Connection

- `better-sqlite3`, **synchronous** API — a single in-process connection, no pool, no await-per-query overhead.
- Singleton cached on `globalThis` so hot reload doesn't reopen the file.
- Pragmas: `journal_mode = WAL` (concurrent readers while writing), `foreign_keys = ON` (so the `CASCADE` deletes actually work).
- Thin helpers: `all<T>()`, `first<T>()`, `run()`, `isoNow()`, `todayKey()`.

## What lives where

| Data | Location | Why |
| --- | --- | --- |
| Curriculum (lessons, puzzles, projects, ideas, badges, missions, levels) | `src/content/*.ts` | Versioned, type-checked, bundled, instantly searchable |
| User data (accounts, progress, XP…) | SQLite | Mutable, private, per-user |

## Tables

### `users`
Account + denormalised gamification counters: `username`/`email` UNIQUE, `password_hash` (bcrypt cost 12), profile fields (`avatar`, `headline`, `github_url`, `website_url`), preferences (`theme`, `notify_missions`), and progress totals (`xp`, `streak`, `longest_streak`, `last_active_date`).

> XP is denormalised on the row because every page shows it; `reward()` is the only writer.

### `sessions`
`token` (PK, 32 random bytes, stored in the httpOnly `bv_session` cookie) → `user_id`, `expires_at` (30 days). Index on `user_id`.

### `password_resets`
Single-use token per user (latest overwrites), `expires_at` (30 min), `used` flag.

### `lesson_progress`
`(user_id, lesson_slug)` PK · `quiz_score`, `quiz_total`, `completed`, `updated_at`. Drives "n of m lessons" per path and continue-where-you-left-off.

### `challenge_attempts` (Thinking Gym)
Append-only rows: `challenge_slug`, `hints_used`, `correct`. XP is only granted when `correct` flips from false → true.

### `debug_attempts` (Error Companion)
Same shape as challenge attempts with `debug_slug`, `solved`.

### `project_progress`
`(user_id, project_slug)` PK · `steps_done` JSON array of ticked step indexes, `completed`, `updated_at`.

### `mission_completions`
`(user_id, mission_slug, date)` PK — the composite key makes "one completion per mission per day" a database guarantee, not an application check.

### `user_badges`
`(user_id, badge_slug)` PK + `earned_at`; badge rules live in `src/content/badges.ts`.

### `notifications`
Generated by `reward()` (XP, level-up, badge, mission) — `type`, `title`, `body`, `href`, `is_read`, `created_at`. Index on `(user_id, created_at)`; the bell marks them read in one UPDATE.

### `portfolio_projects`
User's showcase: name, description, tech, difficulty, optional `github_url`/`live_url`/`completed_date`.

### `bookmarks`
Polymorphic: `ref_type` ∈ `lesson | idea | project` + `ref_slug`, PK on `(user_id, ref_type, ref_slug)`.

### `ai_conversations`
Persisted Builder AI chat: `mode`, `title`, `messages` JSON array, `updated_at`.

## Shape of the data

- **13 tables**, all keyed by `user_id` with `ON DELETE CASCADE` — deleting an account removes every trace (`deleteAccountAction`).
- ISO-8601 TEXT timestamps everywhere; single-day fields use `YYYY-MM-DD`.
- Denormalised counters (`users.xp`) where read volume is high; normalised junctions where the relationship is many-to-many (`user_badges`, `bookmarks`).

## Backup / reset

```bash
cp data/builderverse.db backup.db   # copy (WAL mode: also grab -wal/-shm if mid-write)
rm -rf data/                        # full reset — next request re-creates schema
```
